# Phase 21: QR Pass Verification & Attendance Log Stabilization

## Objective
Diagnose and resolve the "Pass rejected" error occurring during admin QR code scanning, ensure TOTP verification succeeds in the Supabase Edge Function, and correctly write valid check-in records to the database attendance log.

## Scope
* **Target Files:**
  * `src/app/admin-scanner.tsx` (Admin scanner app view)
  * `src/hooks/use-attendance.ts` (Scanner API caller hook)
  * `supabase/functions/attendance/index.ts` (`scan` / `verify` action handler)
* **Target Database Table:** `attendance_logs` / `memberships`

---

## 1. Task: Payload & Action Protocol Alignment
**Problem:** The payload structure generated by `member-qr.tsx` may not match what `admin-scanner.tsx` parses and sends to the Edge Function `scan` action.
**Implementation Steps:**
* Verify the QR payload schema output from `member-qr.tsx` (e.g., JSON containing `{ memberId, code, timestamp }` vs raw TOTP string).
* Inspect `admin-scanner.tsx` to ensure `onBarCodeScanned` correctly parses the payload prior to firing the API call.
* Align request body structure for the Edge Function `scan` action.

---

## 2. Task: TOTP Verification & Clock Skew Tolerance
**Problem:** Small time drifts between the device running Expo and the Supabase Edge Function server cause valid TOTP tokens to be rejected immediately.
**Implementation Steps:**
* Locate the TOTP verification block in `supabase/functions/attendance/index.ts`.
* Ensure `ATTENDANCE_ENCRYPTION_KEY` is successfully decrypting the user's secret seed during verification.
* Increase the TOTP verification window tolerance (`window: 1` or `window: 2`, allowing $\pm 30\text{--}60$ seconds drift) to accommodate client clock variations.

---

## 3. Task: Member Eligibility & Database Log Insertion
**Problem:** Even if the TOTP is valid, the function may reject scans due to missing member profiles, inactive membership statuses, or failing database inserts.
**Implementation Steps:**
* Inspect the member status query in the Edge Function to ensure test accounts are marked `active`.
* Ensure the function executes an `INSERT INTO attendance_logs` on successful verification.
* Return specific error codes (`EXPIRED_MEMBERSHIP`, `INVALID_TOTP`, `MEMBER_NOT_FOUND`) instead of generic rejections to pinpoint failures.

---

## 4. Task: Real-Time UI & Relay Trigger Integration
**Problem:** The scanner screen shows "Pass rejected" while the attendance dashboard shows 0 check-ins.
**Implementation Steps:**
* Handle successful HTTP `200` responses in `admin-scanner.tsx` by displaying "Pass Verified" with member name/photo.
* Trigger a background fetch to the local relay hardware endpoint (e.g., `http://<PI_OR_LOCAL_IP>:5000/unlock`) upon successful verification.
* Refresh the attendance dashboard list view in real time.
